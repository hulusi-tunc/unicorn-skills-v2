# Lean kit: the AI reads only what the moment needs

Goal (owner, 2026-10-06): less for the AI to read before it can start, nothing read that the project
does not use. Measured at about 4 characters a token.

## Where the reading goes today

| When | What | Tokens before | Aimed | Done (measured) |
|---|---|---|---|---|
| Every message in a project | `AGENTS.md`, skill descriptions, reply style, reviewer list | ~7,800 | ~4,000 | ~5,100 |
| Every `/design-screen` | the workflow plus every guide it names | ~23,300 | ~12,000 | ~13,000 |
| Every `/check` (three reviewers) | guides each reviewer loads before reviewing | ~18,000 | ~0 | ~4,100 (their core guide only) |
| Every `/commit` | `dev-conventions` (Jira, never main: both overruled) | ~1,800 | 0 | 0 |
| `/setup` once | new and joined branches and the helper's build steps, all read | ~5,000 | ~2,300 | ~2,400 |
| Every session on the kit itself | `dev/NOTES.md` | ~9,000 | ~2,500 | ~3,200 |

Status (2026-10-06): phases 1 to 4 done, each phase's tests green. Every message lands at ~5,100,
not ~4,000: the rulebook kept every rule (12.9 KB, not 8 KB), and `kill-ai-slop`'s 1 KB description
is still listed (phase 5). The forwarders were kept (see `dev/HISTORY.md`, Lean kit).

The rulebook grew from 1,614 tokens after the last diet (September) to ~4,200 now.

## Found

- The kit's own 14 skills are 157 KB; about a quarter applies here. Four cover accessibility from
  different angles and disagree (touch target 44 or 48, toast time, focus style). Several contradict
  the rulebook: em dashes in example copy (`accessible-content`, `inclusive-design`), "comments
  explain why" and `TODO(#412)` (`no-slop`), uppercase tracked labels (`ui-design`, `no-slop`),
  editing `components/ui` and importing it in screens (`shadcn-ui`), JSDoc and comments
  (`figma-implement-design-new`), stakeholder sign-off (`ux-strategy`), ease-in exits and 700 ms
  (`interaction-design` against `emil-design-eng`), "reduced motion is not zero" (`emil-design-eng`
  against `/tokenize`). Bugs: `no-slop` points at `taste/TASTE.md` and a missing
  `accessibility-process`.
- Nothing routes to `brandkit`, `imagegen-frontend-web` or `imagegen-frontend-mobile` (93 KB) except
  one Routing line; most agents have no image tool. Their descriptions cost ~450 tokens a message,
  and `imagegen-frontend-web` can fire on "design a landing page" (~10k tokens for nothing).
- `prototyping-testing` (A/B sample sizes, click tests), `ux-strategy` (RACI, HEART) and
  `design-systems` (Figma modes, its own naming and icon system) are agency tools the kit does not
  use; each has a few lines worth keeping in a workflow.
- Reviewers preload skills: `bug-hunter` both platform guides though it only runs tools;
  `code-reviewer` five; `slop-checker` also reads `kill-ai-slop/references/taxonomy.md` (20 KB) for
  ids the gate already names. `design-reviewer` preloads `web-design-guidelines`, which fetches 8 KB
  from GitHub, and has no fetch tool. All three name `project/IDEAS.md`, which nothing creates.
- `/setup` holds three branches in one file: new project (9 KB), joined project (6.5 KB), the
  helper's build steps (4.5 KB). Every run reads all three.
- Repeated rules: `/commit` `## Rules` repeats the rulebook; `/design-screen` step 7 repeats "App
  structure", step 3 repeats step 0; "Working together" repeats what `team-sync.mjs` prints; the
  rulebook's "Skills" and "Paths" are kit history and commands the workflows already give.
- The start-of-chat sync prints "no GitHub home" every chat while the rulebook says not to mention
  it; the list of arrived commits has no cap.
- The two Vercel guides ship compiled `AGENTS.md` files (182 KB). Gemini CLI reads every file named
  `AGENTS.md` below the folder (its `context.fileName`), and OpenCode and Cursor may attach nested
  ones: up to ~45k tokens a message there. Unverified; Claude Code does not.
- `bin/update-project` puts the five `.claude/scripts` forwarders into every project at its first
  `/sync`, so they never go away, though nothing reads them now that old hooks are rewritten.
- Stale: `/sync` step 6 says the kit is not a git repo.

Outside the kit, on the owner's Mac only: Claude Code's global plugins list about 100 more skills
on every message, and the taste-skill plugin repeats `brandkit`, both `imagegen` skills and
`redesign-existing-projects`. Designers do not have these.

## Plan

Each phase ends with every suite in `dev/NOTES.md` "How to test" green and `bin/adapters --check`;
tests that pin moved wording are repointed, never deleted. Commits small, one purpose each.

### 1. Every message
1. `AGENTS.md` to ~8 KB, every rule kept or moved, none lost (checked by keyword as in the last
   diet): "Joined projects" to `.designkit/rules/joined.md` behind one line ("`"joined": true`: read
   it"); "After handover" to `.designkit/rules/handover.md` behind one line; "Working together" to the
   lines the script does not print; "Skills" to `dev/NOTES.md`; "Paths" cut to what no workflow
   says; "Quality" review detail into `/check`. Kept every message: replies, no comments, the slop
   list, tokens, the folder map in short, before designing, git safety, routing.
2. Every kit-owned skill description under 200 characters.
3. Remove `brandkit`, `imagegen-frontend-web`, `imagegen-frontend-mobile`: folders, lock, upstream
   record, notices, Routing line, README count (nine to six), the upstream test count.
4. `team-sync.mjs --start`: no "no GitHub home" line; arrived commits capped at 10 and "N more".

### 2. Each task
1. The kit's own 14 skills to 7:
   - `accessibility` (new, ~8 KB) from `inclusive-design`, `accessible-content`,
     `adaptive-interfaces`, `motion-sensitivity`: one value for each rule, the kit's focus rule, no
     em dashes, no deliverable templates.
   - `ui-design` ~5.5 KB (charts to `references/charts.md`, read only for a chart; breakpoints kept).
   - `interaction-design` ~4 KB (states, loading, feedback; durations only in the motion guide).
   - `no-slop` ~7 KB (contradictions and broken paths fixed; what the gate enforces left to it).
   - `emil-design-eng` ~8 KB (motion only, one easing and duration source matching the motion
     tokens, the course promo and library-author advice out).
   - `figma-implement-design-new` ~3 KB, `shadcn-ui` ~2 KB, both rewritten to the kit's rules.
   - Dropped, their few useful lines moved: `design-systems` (token tiers into `/tokenize`),
     `ux-strategy` (problem framing into `/setup` step 3), `dev-conventions` (hunk review and the
     split example into `/commit`), `prototyping-testing` (nothing; the reviewer already holds the
     heuristics).
2. `/setup` split: `SKILL.md` the new-project steps; `joined.md` read only when joined; `build.md`
   read only by the helper or after step 6. Step 1's upstream check skipped when the kit checked
   within 7 days, diffs capped; the joined history read capped at 200 lines.
3. `/commit`: no `dev-conventions`, `## Rules` cut to the refused-hook procedure.
   `/design-screen`: no restated folder rules, one "sizes missing" branch, the platform guide opened
   only for a platform question.
4. Reviewers: no preloaded skills, "open the platform's guide when a finding needs it"; no taxonomy
   read; `web-design-guidelines` only under `/check all` or when asked; `IDEAS.md` lines removed;
   the shared "Scope and time" block once, in `/check`, passed with the scope.

### 3. A project gets only what it uses
1. Platform pruning: `/setup` (and the joined branch, from `package.json`) writes `"skillsOff"` in
   `.designkit/workspace.json`: web drops `vercel-react-native-skills`; mobile drops
   `vercel-react-best-practices`, `shadcn-ui`, `web-design-guidelines`; both keeps all.
   `bin/update-project` and `check-upstream.mjs` honour it; the kit itself keeps everything.
2. Borrowed skills installed without their `AGENTS.md` and `README.md` (change detection reads
   upstream git, so the check is unaffected).
3. `bin/update-project`: a retired list, so dropped and merged skills leave existing projects
   (unchanged copies only; a changed one is kept and named). Forwarders deleted from the kit and
   swept from projects when unchanged.
4. `/sync` step 6 corrected.

### 4. Sessions on the kit
`dev/NOTES.md` to ~10 KB: who it is for, how the owner works, layout, the rules each area must keep,
how to test, what is next. The dated decision log moves to `dev/HISTORY.md`, read when touching that
area. `AGENTS.md` "Kit or project" says which to read.

### 5. Later, only if the numbers say so
Guides out of the skill list: the 7 workflows stay skills (designers type them); the guides move to
`.designkit/guides/` and are read by path when a workflow or the Routing names them. Saves another
~600 tokens a message, costs a change to how borrowed skills install and about ten test edits.
Decide after phase 3 is measured.
