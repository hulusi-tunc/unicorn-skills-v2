# Working on the kit: read this first

The kit's memory, in the repo, because the owner works across several accounts and a new session
starts with no history. This file is the current state; `dev/HISTORY.md` holds every decision with
its reason and proof, dated: read the entry for an area before changing it. Settle something new:
one line under "Settled" here, the full entry at the end of `HISTORY.md`, same session.

`dev/` is for working on the kit. `bin/new-project` does not copy it into projects.

## Who it is for

Designers with little or no technical background, doing UI/UX work by talking to Claude ("vibe
coding"). They should never need to understand how the kit works. It has to set everything up and
stay out of their way, so they can focus on the design.

The owner's two biggest costs, which the kit exists to remove:
1. Re-explaining a project to every new session (the setup phase).
2. Fixing AI slop screen by screen.

## How the owner likes to work

- Plain language, short sentences, no jargon. Give one next step, not a briefing.
- No em dashes anywhere: chat, docs, UI copy.
- No explanations in code files (see `CLAUDE.md`). This applies to the kit's own scripts too.
- Nothing updates or changes without asking. Report, advise, let the owner choose.
- Reuse maintained tools from others rather than building from scratch, but weigh the upkeep.
- The repo is private. See "Licences" below before ever making it public.

## Layout

| Path | What it is | Copied into projects? |
|---|---|---|
| `AGENTS.md`, `CLAUDE.md`, `README.md` | Rules for every agent; a one-line loader for Claude Code; the front page | Yes |
| `.agents/skills/` | All skills, the seven workflows included | Yes |
| `.designkit/` | Scripts, reviewer sources, git hooks, policy, the OpenCode plugin, `rules/` read only in one situation (joined, after handover) | Yes (not `node_modules`, not `state/`) |
| `.claude/`, `.codex/`, `.cursor/`, `.gemini/`, `.github/`, `.opencode/`, `opencode.json` | Each tool's files, generated by `bin/adapters` | Yes (not `.claude/scripts`, the forwarders) |
| `project/` | Empty folders the commands write into | Yes |
| `bin/install` | Installs or updates what the kit needs on a Mac; an AI agent only when none is found | No |
| `bin/new-project` | Makes the folder it runs in a project, the app folder inside | No |
| `bin/adapters`, `bin/update-project` | Regenerate the tool files; move an old project | No |
| `dev/` | These notes, `HISTORY.md` (every decision and its proof), plans, specs and the test suites | No |

A project is the designer's own folder, named after the project, holding two repos: the folder
itself is the docs repo (this kit plus decisions, specs, reviews; the agent always opens here), and
`<Name>-app` inside it is the app repo (code only; the dev team clones just this), ignored by the
docs repo's `.gitignore`. `.designkit/workspace.json` points at the app (`"app": "<Name>-app"`) and at
the kit (`"kit"`); the app's local git config `designkit.docs` is `..`.

- **The slop gate**: `kill-ai-slop`'s patterns plus `dk-01` to `dk-11`; after each save, on each app

  TypeScript 6 parser pinned.
- **`/setup`**: five things asked; writes `PROJECT.md`, `TASTE.md`, `DECISIONS.md`; a background
  helper builds the app from `build.md`; joined code follows `joined.md`; stops before `/tokenize`.
- **Settings and guard**: no AI attribution; Figma writes denied; staging everything at once,
  skipping the commit check and force pushes refused, also through `git -C`; never edit
  `permissions` (auto mode refuses it). The guard also refuses a script whose text names a refused
  command: write such a script to a file first.
- **Reply style**: `.claude/output-styles/designer.md`: result first, one next step, at most one
  yes-or-no question, long material in files.
- **Token diet**, then **Lean kit** (2026-10-06): kit files are for the AI; what every message
  reads stays small, short not cryptic, a few words of why. Situational rules live in
  `.designkit/rules/`, workflow branches in their own files, guides load only when named.
- **Starting from the link**: README "For your AI agent": clone to `~/design-kit`, `bin/install`,
  `bin/new-project`, then setup in the same chat.
- **Install**: git, Node 22 or newer, rsync; an agent only when none is found; the gate's parser and
  self-test.
- **Permission prompts**: designers use auto mode; the kit carries no allow list.
- **App structure** and **the data door**: features by business job, `DS<Part>` wrappers, `src/api`
  with five mock scenarios, the contract in the app; gate `dk-08`, `dk-09`.
- **Working together**: everyone on `main` until handover; `team-sync.mjs` does all git; claims in
  `project/WORKING.md`; first pushed wins, the other side saved in `project/reviews/conflicts/`.
- **Existing projects and lighter checks**: `join-existing.mjs`; checks in levels (gate on save,
  quick checks on commit, `/check` when asked, `/check all` before handover).
- **Any agent**: `AGENTS.md` is the rulebook, skills in `.agents/skills`, machinery in
  `.designkit/`, tool files generated by `bin/adapters`; proven live only in Claude Code.
- **Responsive by kind of project**: `## Screen sizes` in `PROJECT.md`; a mobile app gets none.
- **The dev's playbook**: `dk-10`, `dk-11`, `project/DEV.md`, `DS<Part>` names, one icon set.
- **Platform guides** (in **Lean kit**): a project keeps only its platform's (`skills-for.mjs`,
  `"skillsOff"`).

## How to test

```
node dev/tests/layout/run.mjs        # the kit's shape, stale paths, neutral words, generated files current
node dev/tests/rules/run.mjs         # each agreed rule read back from where it lives; must be 42/42
node dev/tests/gate/run.mjs          # 72 probe files plus the self-test; must be 72/72
node dev/tests/gate/staged.mjs       # the commit check on new problems only; must be 12/12
node dev/tests/checks/run.mjs        # status file, review reminder, quick checks; must be 35/35
node dev/tests/hooks/run.mjs         # the guard, the two git checks, hook.mjs in every tool's format
node dev/tests/adapters/run.mjs      # generated files, merging into a project's own, the OpenCode plugin
bash dev/tests/upstream/run.sh       # a fake change to a borrowed skill in a sandbox; must be 14/14 (network)
bash dev/tests/install/run.sh        # install, new-project, joining, the gate in a project; must be 65/65
bash dev/tests/update/run.sh         # old projects, built from commit 0b6743e, moved to this layout; must be 41/41
bash dev/tests/team/run.sh           # two designers on local bare repos, no network; must be 41/41
node .designkit/scripts/slop-gate.mjs --self-test
bin/adapters --check
```

Live behaviour checks: make a throwaway project with `bin/new-project <folder>`, then run
`claude -p "<request>" --model sonnet --permission-mode acceptEdits --output-format json </dev/null`
inside that folder and read `.result`. Headless runs cannot answer permission prompts, so a
command that is not pre-allowed fails there; that makes this the way to prove designers will see no
prompts.

The gate probes were written by a review of the kit: each one is a case the gate once got wrong or
a case it must never get wrong. The upstream test builds a sandbox home folder, so it never touches
the real kit or the real cache.

End to end (not scripted, takes minutes and the network): make a throwaway project with
`bin/new-project <folder>`, then follow `/setup` steps 6 and 7 (and `build.md`) by hand for web and for mobile, and
check lint, knip and the gate are green and that a commit with a comment in it is refused.
